## Layout

- `web/src`: React website (Vite). `main.tsx` wires the app together. `components/shell/` is the shell since 2.43: `AppShell`, `TopBar`, `SectionNav`, `SectionHeader`, `SectionView`, `EditorPanel` (Mimic, the copy editor, `SoundEditor` and `ActivityView` open in it; a sheet on phones) with `Splitter`, `HeaderRibbon`, `Landing`, `DemoBanner`. `shell.ts` carries editor and view requests as window events, `sections.ts` remembers each section's place, `prefs.ts` / `motion.ts` / `appearance.ts` keep the appearance choices, and `ui-sync.ts` syncs the host's style with the companion's `ui.json`. `ribbon/` is the header ribbon's pure logic (`envelope.ts`, `machine.ts`, `draw.ts`). `focus-clear.ts` keeps keyboard focus clear of the notices and the player; `focus-follow.ts` moves focus on when a control takes itself away. `controller.ts` owns connection state. `arrange.ts` is the pure sound sorting and filtering logic. The Mimic panel is `components/MimicPanel.tsx` plus `components/mimic/`, with pure helpers in `mimic/selection.ts`. `version.ts` has the `FEATURES` gate table.
- `web/src/demo/`: the example session (`model.ts`, `engine.ts`, `history.ts`, `drafts.ts`, `voices.ts`, `sentences.ts`, `library.ts`, `dsp.ts`), loaded lazily; `tests/unit/demo-engine.ts` drives it in unit tests. `DEMO_COMPANION` in `model.ts` is the companion version the example claims: raise it only together with the example's support for the ops of the newly covered features. `tests/unit/demo-coverage.test.ts` enforces this (every op the website sends up to `DEMO_COMPANION` is answered or honestly refused).
- `tests/e2e/helpers/`: shared e2e steps. `harness.ts` has the fixture (the mock companion, `noPublicRelays`, failure diagnostics from every page), `shell.ts` the section and editor-panel lookups, `playback.ts` the player's. `tests/shots/` holds manual screenshot and ribbon-performance probes (`playwright.shots.config.ts`); they assert nothing and are not in CI.
- `companion/`: .NET 10 Windows companion (`src`), its xUnit tests (`tests`) and the mock-Soundpad harness used by e2e tests (`harness`). Mimic capture lives in `MimicCapture.cs` / `BridgeMimic.cs` and transcripts in `MimicTranscript.cs`; `UiPrefs.cs` / `BridgeUi.cs` keep the host's shared style in `<data>\ui.json` (2.43, host only, `uiRevision` in the snapshot); `VoiceReplayLibrary.cs` reads Voice Replay Studio's library read-only (never write to it; the harness uses `harness/VoiceReplayFixture.cs`); `harness/MimicFixture.cs` and `harness/TranscriptFixture.cs` are their test stand-ins (the harness always uses them, so e2e never touches real audio or Whisper).
- Stage H (2.44) joins the Bridge in one place, `companion/src/BridgeStageH.cs` (`ExecuteStageH` → backups, updates, Organize, setup; `StageHStarted` once per process; the update/restore/apply cross-checks), with one partial file per package: `BridgeBackups.cs` (`Backups.cs`, `BackupSnapshot.cs`, `BackupRestore.cs`, `BackupSettings.cs`, `OfflineRestore.cs` for `--restore-state`), `BridgeUpdates.cs` (`Updater.cs`, `UpdateRelease.cs`, `UpdateSwap.cs`, `UpdateHandoff.cs`, `UpdateModels.cs`; `companion/update-fixture/` and `scripts/update-swap-test.ps1` for the process-level test), `BridgeOrganize.cs` (`Organize.cs`, `OrganizePlan.cs`, `OrganizeApply.cs`, `NativeTree.cs`, `MissingFiles.cs`, `QuietRule.cs`) and `BridgeSetup.cs` (`SetupState.cs`, `SoundpadDiagnosis.cs`, `HotkeyChord.cs`, `HostHotkeys.cs`). The harness side is `harness/HarnessStageH.cs` (the stdin verb registry and the `MockReady` / `BeforeBridge` / `BridgeMade` / `BeforeServer` / `AfterBridge` / `RollbackFixture` hooks) with `HarnessBackups.cs`, `HarnessUpdates.cs`, `HarnessOrganize.cs` and `HarnessSetup.cs`. On the website, `web/src/stage-h.ts` is the shared context (`useStageH`, `organizeActive`), the pure modules are `backups.ts`, `updates.ts`, `organize.ts` and `shortcuts.ts`, and components are in `components/backups/`, `updates/`, `organize/`, `setup/` and `settings/`. Every Stage H op carries its details in the command's `body`. Tests never register a real Windows hotkey (`HostHotkeys.ForbidWindowsHotkeys`), never read the real `%APPDATA%\Leppsoft` (`UseLeppsoftFolder`) and never download a real release (`--update-source` takes loopback only). Docs: `docs/BACKUPS.md`, `docs/UPDATES.md`, `docs/ORGANIZE.md`, `docs/SETUP.md`.
- Whisper's native DLLs are embedded resources written to `<data>\native\whisper-1.9.1\runtimes\win-x64\`. Whisper.net probes `<folder of RuntimeOptions.LibraryPath>\runtimes\win-x64`, so keep that layout. Check single-file loading with `SoundpadWeb.exe --transcribe-file <wav> --verbose` on a published EXE; the Whisper model is at `%LOCALAPPDATA%\SoundpadWeb\models\` on the owner's PC.
- `mimic/`: Voice Replay Studio V1.1 desktop app (WPF, NAudio 2.2.1, Whisper.net), imported unchanged in 2.4.0. It shares no code with the companion; the companion's Mimic is a port onto NAudio 3.3.
- `docs/MIMIC.md` describes Mimic; `docs/ROLLBACK.md` lists restore points and must gain a row for every release.
- CSS is layered (2.43), imported by `main.tsx` in this order: `tokens.css` → DM Sans (`@fontsource-variable/dm-sans/wght.css`) → `studio.css` → `controls.css` → `mimic.css` → `voices.css` → `sentences.css` → `shell.css` → `playback.css` → `surfaces.css` → (2.44, Stage H) `backups.css` → `updates.css` → `organize.css` → `setup.css`. Later files override earlier ones at equal specificity; no `!important` outside the reduced-motion rules. Ownership rule: each file's header comment says which components it owns (`controls.css` the shared primitives and focus ring, `shell.css` the shell, editor panel, sheet and notice dock, `mimic.css` Mimic, `playback.css` the player, tiles, Kick, Spotify and ribbon, `surfaces.css` dialogs, settings and the example, `voices.css` / `sentences.css` those views, `backups.css` the backup and restore pieces, `updates.css` the update offer, chip and dialog, `organize.css` Organize mode, the tile check, the Review changes panel, Needs attention and the shared-copy preview, `setup.css` the setup guide, the shortcut editor and the hotkey pickers). Style a component only in its owner's file; `studio.css` holds the older consolidated rules and only shrinks (fold a rule away when an owner file fully overrides it). Before changing a selector, `grep` it across all the files: `studio.css` often still has an older rule for it. For CSS-only cleanups, use a temporary Playwright spec with `toHaveScreenshot` (`maxDiffPixels: 0`, `animations: 'disabled'`) and, as 2.43 did, a dump of computed styles: record a baseline with `--update-snapshots` on the unchanged code, confirm a second run passes, change the CSS, rerun, then delete the spec and snapshots. Exact-pixel snapshots are machine-specific, so don't commit them (2.9.2 and 2.43 used this method). `--player-height` and `--notice-height` (published by `Player.tsx` and `Notifications.tsx`) feed the scroll-padding that keeps focus clear of the player and the phone notice dock; count them in any new bottom-anchored scroller. At the top, `--topbar-bottom` (`TopBar.tsx`, the sticky header at 1000 px and below) and `--dialog-title-height` (`Modal.tsx`, a dialog's sticky title row) do the same through scroll-padding-top; `focus-clear.ts` counts both.

Use the one bundled with their original Mimic folder: `..\Mimic (Voice Replay Studio)\.tools\dotnet\dotnet.exe` (10.0.402; the folder moved to `A OF THE I\Apps` in November 2026), e.g. `test companion/tests/SoundpadWeb.Tests.csproj -c Release` and `build companion/harness/SoundpadWeb.Harness.csproj -c Release`.

- WebKit (Safari's engine) also runs in CI: `npx playwright install webkit`, then `$env:TEST_BROWSER='webkit'; npx playwright test --output test-results/webkit`. Expect 9 skipped (2.41): besides those 5, the loopback HTTPS test, the no-WebRTC guest test, the Edit copy Loop preview test and the notices-never-cover test (it needs the example, which can't play audio there) are skipped, because hosts never use Safari and headless WebKit often refuses to play audio. Playwright's Firefox build is blocked from starting on the owner's PC (`spawn UNKNOWN` / permission denied, likely Smart App Control). Don't change that security setting to run it.
- Since 2.36 the companion is a desktop app with a WebView2 window. The owner often plays games on this PC, so run every check headless or hidden: e2e is headless; start the EXE with `--hidden-window` (or `--no-window --no-browser`) and redirected stdio, and `scripts/smoke-exe.ps1 -Hidden` (it needs PowerShell 7, not installed here). Enter on a piped stdin quits it.
- The e2e suite runs against the Vite dev server in the working tree. Don't edit `web/src` while it runs, because hot reload will affect the results.

## Conventions

- Bump `package.json` (and the two matching `package-lock.json` entries) and `companion/SoundpadWeb.Companion.csproj` `<Version>` together for each release, tag `vX.Y.Z`, and add the release to `docs/ROLLBACK.md`. The header and footer read the version from there through the `__APP_VERSION__` define in `vite.config.ts`.
- Bump `REQUIRED_COMPANION` in `web/src/version.ts` only when the website depends on a new companion feature.
- Never set `disabled` on a control just because its own command is running: Chrome drops keyboard focus from a control that becomes disabled. Use `aria-disabled` and ignore presses while busy (2.13.1–2.13.3). The slow-connection e2e test covers this.
- Every new companion-dependent control must be gated with `supports(state.companionVersion, feature)`; add the feature and its first companion version to `FEATURES` in `web/src/version.ts`, and its name to `FEATURE_NAMES` there (Settings lists what an update adds). The website is always newest, so hosts on older companions see it.
- Dependencies: only adopt releases at least two weeks old, and don't force major-version overrides under tools. Open item (2026-10-31): moderate `minimatch` < 11.0.1 advisory inside ESLint/typescript-eslint (dev-only). Update once ESLint depends on `minimatch` 11 and that release is two weeks old; see CHANGELOG 2.11.2. Checked again for 2.13.5: `minimatch` 11.0.1 was published 2026-10-27, and ESLint 10.14.0 (2026-10-30) still depends on `^10.2.6`. Checked again 2026-11-10 (after 2.27.0): no change, and no dependency update was two weeks old yet (Playwright 1.65.0 2026-11-05, Vitest 5.1.0 2026-11-02, Vite 8.3.7 and typescript-eslint 8.72.2 2026-11-09, ESLint 10.14.0 2026-10-30); the earliest become eligible from 2026-11-13.
- Soundpad reads commands in the Windows ANSI code page, not UTF-8 (2.15.9): send every command through `SoundpadPipe` (it encodes with `SoundpadText`), keep app-made names ASCII, and keep `MockSoundpad` decoding code page 1252 so tests see what the real Soundpad stores.
- Soundpad removes a category's sounds along with the category (measured 2.16). The companion uses that only for its own Temp category at session end, and only when every entry in it is a retired temporary file of its own (`RemoveTempCategory`).
- Never loosen validation of persisted data (`state.json`, the managed-audio journal, e.g. the 16 MiB staged-input check): older companions would reject the newer data and rolling back would break. After changing anything persisted, rerun the rollback test in `docs/ROLLBACK.md` (harness `--make-rollback-fixture`) against the v2.3.1 companion.
- Work on a branch. When a requested feature is done and verified, merge it to `main` and push the release tag yourself (the owner asked for this); confirm the Pages and release runs succeed.
- Push to `main` first and wait for its CI run to pass, then push the `vX.Y.Z` tag. Never tag first: a tag whose CI fails gets no release and no EXE, and public tags are never moved or deleted. v2.14.3 and v2.15.4 are source-only for this reason.
