## Roll back the Windows companion

1. Close the running companion (Enter or Ctrl+C in its window).
2. Download `SoundpadWeb.exe` from the release you want in the table above.
3. Run it as usual.

Your data in `%LOCALAPPDATA%\SoundpadWeb` keeps working (Temp's 16 MiB per-sound limit is never raised for this reason, see 2.10.1):

- 2.4.0 adds one optional setting (`guestMimic`) to `state.json`. Older companions ignore it.
- 2.5.0 adds `models\` (the Whisper model, if you downloaded it) and `native\` (Whisper's libraries). Older versions ignore both; delete them to free ~150 MB if you go back for good.
- Mimic clips are ordinary Temp entries, so older companions manage, keep or clean them up like any upload.
- The Mimic buffer is never written to disk, so there is nothing to remove.

### Tested, not just argued (2.10.1)

On the owner's PC, the **pre-Mimic v2.3.1 companion**, built from its tag, was started on data folders written by 2.10.1. One was left mid-session and one after End Hosting. Both held Mimic clips, a trimmed copy, an echo copy and the `guestMimic` setting. The old companion started normally, loaded all three Temp sounds without any "invalid data" error, and shut down cleanly, the same as the current version on the same data.

One expected side effect: v2.3.1 does not know `guestMimic`, so it drops that setting when it saves `state.json`. If you go back and later upgrade again, **Guest Mimic** is simply off, which is also the default. Turn it back on in Session & access.

To repeat the test for any older version:

```powershell
companion\harness\bin\Release\net10.0-windows10.0.19041.0\win-x64\SoundpadWeb.Harness.exe --make-rollback-fixture C:\temp\rollback-data open
companion\harness\bin\Release\net10.0-windows10.0.19041.0\win-x64\SoundpadWeb.Harness.exe --mock-only   # prints TEST_PIPE <name>
<older>\SoundpadWeb.exe --data-dir C:\temp\rollback-data --pipe <name> --no-browser --site https://example.invalid/
```

### Mixed versions are tested too (2.10.2)

Usually only one half is rolled back. Both pairings were run on the owner's PC with the v2.3.1 companion harness and website built from the tag:

- **New website with an older companion:** everything the old companion supports works, and newer controls (Mimic, transcripts, F6, Edit copy, effects, Guest Mimic) are hidden instead of failing.
- **Older website with the new companion:** works. Saving permissions from the old website turns Guest Mimic off, since it does not know that setting.

## Roll back the website

The live site always serves `main`. To publish an older version from your fork:

```bash
git checkout -b rollback v2.3.1
```

```bash
git push origin rollback:main --force-with-lease
```

The second command replaces `main` on GitHub, so only do it when you mean to. GitHub Pages then redeploys that version. To get Mimic back later, push the newer tag the same way.

You don't need to roll back the website for an older companion to work: the 2.4 website hides Mimic when the companion is older than 2.4, and the rest works with 2.3 companions.

## Run an old version locally without touching GitHub

Download **Source code (zip)** from the release page, or:

```bash
git worktree add ../soundpad-web-2.3.1 v2.3.1
```

Then follow that version's README to build it.
