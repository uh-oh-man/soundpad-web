# Protocol 1

The executable and website must agree on `v: 1`. Types and strict guest-command schemas live in `web/src/protocol.ts`; native records and validation live in `companion/src/Models.cs` and `Bridge.cs`.

Loopback: `ws://127.0.0.1:<ephemeral port>/bridge`. Require the exact configured website Origin and numeric loopback Host, then `{token}` within five seconds. No token in WebSocket URLs. One host tab owns the bridge. Requests are `{actor,command}`. Only this authenticated browser can set `actor: host`; relayed commands always use the fixed guest actor, regardless of a peer-provided identity. The native bridge independently enforces guest permissions. Replies are `{type:"ack",id,ok,error}`; snapshots are `{type:"state",state}`. Maximum inbound frame aggregate 200,000 bytes, 20 requests/second, serialized queue at most 24.

Commands: `{v,id,at,op,...}`. UUID `id`, UTC Unix milliseconds `at`. Allowlist: `play`, `stop`, `counter`; host-only `reset`, `permissions`, `icon`, `refresh`. `play` requires `soundId` and `libraryVersion`; `counter` requires `delta: -1 | 1`. Reject playback older than five seconds and other commands older than 30 seconds, including after queuing. No retries for playback. Native persistent receipts deduplicate accepted IDs for at least two minutes. Fresh UUID per intentional action. A repeated accepted ID acknowledges without applying again. An expired retry is rejected, never reapplied. Queue overflow rejects immediately.

Guest transport: Trystero 0.26 Nostr strategy. Random 192-bit room and 256-bit password, unique per host session. Invitation fragment carries `{v,room,secret,publicKey}` only. It does not carry the native token or signing private key. Host browser keeps its ECDSA P-256 signing key in sessionStorage so a same-tab refresh can recover. Starting the executable again creates a new native token and new browser session identity.

Peer discovery alone is not authentication. Guest sends `hello` with a random nonce. Host sends `welcome` with a signature over JSON `[1,room,nonce,hostPeerId,guestPeerId]` plus the initial snapshot. Guest pins the invitation public key and accepts later state, ACK and revoke messages only from the peer that verified this signature. Guests cannot impersonate the host using the shared room password. Acknowledgments are application-level; Trystero send completion alone is insufficient. Each host authenticates up to 12 guests. Per-peer 12 message/second limit (host receive); malformed commands close/deny the peer. Incoming guest payloads are capped at 8 KiB before transfer; guest snapshot receive budget 16 MiB.

State revision orders snapshots. Full library is sent on welcome and library-version changes; `tick` carries lightweight authoritative state and a library version, with a full resync on mismatch. Counter and permissions live in the companion; no guest localStorage authority. Library refresh every 30 seconds, playback status every two seconds, library revalidation immediately before play. Polling and commands share the native serial gate. Playback identity is intentionally not guessed: Soundpad's documented status API does not reliably identify manually initiated current tracks.

Disconnect uses an in-memory denied-peer list and closes that connection. Since an invite is a bearer credential, a person can rejoin with a new browser identity until the host **replaces the invite**. Rotation revokes current peers, leaves the room, creates new cryptographic material, and preserves local counters/icons. Old invitation refreshes may show Host unavailable rather than Access revoked if they missed the explicit revoke message.

This is a small-room mesh, not a large broadcast service. Public relay availability, browser background suspension, NAT/firewalls and browser loopback policies can prevent connections. No hosted application backend, custom signaling server, audio relay, or cloud database exists.

## Playback intents (2.35)

The paragraphs above describe the original protocol; these rules replace the ones they contradict.

- **Intents.** `play`, `startAt`, `region`, `audioPlay`, `reverse`, `stop`, `panic`, and `trimAudio` / `mimicClip` / `mimicLibraryImport` sent with `autoplay: true` are playback intents. The companion numbers them in the order they arrive (never by client clocks) and only the newest may start audio. A superseded, expired (older than 5 s; 30 s for `stop`, `pause`, `panic`) or suspended intent is acknowledged `{ok:true, data:{superseded:true, reason:"newer"|"expired"|"suspended", played:false}}`. It is never an error and never plays later. `seek` and `pause` are bound to one playback (`soundId` + `epoch`); for a playback that is gone they are acknowledged `{superseded:true, reason:"stale"}`.
- **Started plays** are acknowledged `{played:true, epoch}`. An `autoplay` command returns its usual data plus `played`.
- **`panic`** (host only): `action:"enable"` stops Soundpad, cancels pending starts and sets the snapshot's optional `playbackSuspended`; `action:"disable"` clears it. While set, guest playback input gets the quiet `suspended` answer. In memory only.
- **Stop and Panic** do not take the native gate; they wait only for the pipe request in flight. Starts hold the gate in an urgent lane, and a start still waiting when a newer intent arrives leaves the queue at once.
- **Durability.** Counter, permissions, icons and settings are on disk before their acknowledgement. Receipts, statistics and activity of plays are written by a background flush about 300 ms later and on clean exit.
- **Loopback limits.** Nothing is awaited in the receive loop. Playback/control ops (`play`, `startAt`, `region`, `stop`, `seek`, `pause`, `panic`, `audioPlay`, `reverse`) have their own bucket of 600 per second; everything else keeps 32 per second and the 16-slot limit for slow work.
- **Coalescing.** Stops that arrive together share one `DoStopSound`. A seek waiting for the gate is replaced by a newer seek; a second pause is answered as stale while one waits. The loopback socket gives the host's own control ops a separate bucket, and the host page counts unanswered control commands per sender (64 per guest, 512 for the host).
- **Guest limits in the host page.** With a 2.35 companion, per guest and per second: 100 control ops, 12 other messages (refused with an acknowledgement, the guest stays), and 400 in total before the guest is dropped. With an older companion every guest message shares the 12 per second, as in 2.34. On a guest page only the verified host is exempt from the flood cut-off. Malformed traffic still drops; a well-formed command with an unknown op or field is refused with "The host's page is older than yours".
- **Versions and clocks.** `hello` and `welcome` carry the page's website version as `site`; a guest sends no op or field newer than the host page knows. Every `state` and `tick` carries `hostNow`, from which the guest keeps its clock offset current.

## Guest identity (2.41)

Up to 2.40 the host page keyed a guest by the participant id the guest's own hello declared, so anyone in the room could claim another guest's id. Since 2.41 the identity is a key the guest proves:

- **Key.** Each guest browser keeps an ECDSA P-256 key pair in IndexedDB (`soundpad-web-keys` / `keys` / `guest-v1`); the private key is non-extractable. Where IndexedDB is unavailable the page makes a key for that page only and tells the guest once (`ConnectionInfo.guestKey: 'page'`).
- **hello `key`.** Every 2.41 guest hello carries `key`, the public key as base64url SPKI.
- **`challenge`.** A host answers a keyed hello that has no valid proof with `{v:1, type:"challenge", nonce, challenge}`: `nonce` echoes the hello's, `challenge` is 32 random bytes (base64url), one per connection, kept in a bounded map.
- **hello `challenge` + `proof`.** The guest sends its hello again with `challenge` and `proof`, an ECDSA P-256 / SHA-256 signature over the UTF-8 JSON `[2,"guest",room,helloNonce,challenge,hostPeerId,guestPeerId]` (on the relay transport both peer ids are prefixed `relay:`, as in the welcome's proof). A proof is therefore worthless on any other connection, room or host page.
- **Identity.** With a valid proof the participant id is `guestIdOf(key)`: the first 16 bytes of SHA-256(`"soundpad-guest-id-v1"` ‖ SPKI), formatted as a UUIDv8 so it fits every existing UUID field. Admission, places, per-guest permissions, history join times, drafts and Keep budgets all follow that id; the display name stays separate. The id relayed to the companion is always this verified id.
- **Unverified.** A hello with no `key` (a page older than 2.41) is admitted under the usual lobby rules as an unverified guest, keyed by its transport peer id with a random id, so nothing granted to another connection or page load is reused; its direct and relay connections count as two guests. The host's lobby requests carry `unverified: true`, and the owner page relays the unverified peers to views (`control.unverified`); older views ignore both.
- Older host pages ignore `key`, `challenge` and `proof`, so a 2.41 guest still joins them as before.

## Voice library (2.41)

New permission `guestLibraryEdit` (default on; also a per-guest override). The host page relays these ops to a 2.41 companion only; its welcome lists `"library"` in `relays`. Every write is audited with who made it and can be undone by its audit group.

- **Read, anyone:** `libraryStatus` (counts, voices, settings, notices; 'history' possible-match notices only for guests allowed Mimic, filtered by the companion and again by the host page for each guest's own `guestMimic`), `libraryList` (filters `query`, `voiceId`, `unassigned`, `tag`, `favorite`, `reviewed`; paging `offset`, `limit`), `libraryGet` (`recordingId`), `librarySearch` (`query`: exact word or phrase across voice recordings and the sounds of categories indexed now), `libraryVocabulary`, `libraryAudit` (to guests, records carry only `{id,title}` or `{id,voiceId,text}`, never paths, asset ids or participant ids), `libraryPreview` (`recordingId`, or a `soundId` a guest may preview only in a category indexed now; `positionMs`/`endMs`, at most 30 s; to guests resampled to 16 kHz, 12 a minute, one at a time).
- **Edit, host or `guestLibraryEdit`:** `libraryEdit` (`recordingId` or `recordingIds` up to 500, with `title`, `tags`/`addTags`/`removeTags`, `favorite`, `voiceId`, `reviewed`, `correctedText`; corrected text on one recording per edit), `libraryRemove` (never deletes the file), `libraryUndo` (`auditId`), `libraryVoice` (`action` `create`, `update` or `delete`, with `voiceId`, `name`, `color`), `libraryWanted` (`action` `add` with `voiceId` and `query`, or `remove`), `libraryAdd` (`soundId` of a Soundpad sound, idempotent per file; a guest may add only a sound in a category indexed now), `libraryRetry` (find a recording's words again). Guests are limited to 60 writes a minute each.
- **Host only:** `librarySettings` (`guestLibraryEdit`, `groupSpeakers`), `libraryIndex` (`categories` by name, or `action` `pause` / `resume`).
- **Into the library:** `draftKeep` with `action:"library"` (needs `guestMimic` and `guestKeep` for a guest) answers `{recordingId}`, or `ok:false` with the library's reason, leaving the draft open. `mimicLibraryImport` takes the same `action`.
- **Mimic history, guests with `guestMimic`:** `historySearch` (`query`, `sourceId`), `speakerGroups`; `speakerName` and `speakerLink` (`sourceId`, also need `guestLibraryEdit`). A `sourceId` that is not the current recording is refused ("Mimic restarted since you looked").
- **Snapshot:** `permissions.guestLibraryEdit` (omitted until the library has loaded) and `voiceLibrary`, a counter that rises when the library, its index, notices or speaker groups change, so pages fetch `libraryStatus`.
- **Files** (under the data folder's `library\`): `voice-library.v1.json` (+ `.bak.json`; a save over 64 MiB is refused), `voice-words.v1.jsonl`, `voice-audit.v1.jsonl` (rotated to `.old.jsonl` past 32 MiB), `sound-words.v1.jsonl`. `state.json` and the managed-audio journal are unchanged.

## Sentences and the speaking palette (2.42)

Built from voice-library recordings and named pieces on them only, never from the raw Mimic history, so a guest never reaches audio from before their join. The only audio the renderer makes itself is silence and a bleep. The host page relays these ops to a 2.42 companion only; its welcome lists `"sentences"` in `relays` (a host page whose `site` is 2.42 or newer also counts). Website gate `FEATURES.sentences = [2, 42]`.

- **Read, anyone:** `sentenceList` (sentences in progress for the asker, kept ones for everyone, with `canBuild` / `canKeep`; each sentence has `canEdit`), `sentenceGet` (`sentenceId`: pieces, overlaps, missing words, versions and which pieces' sources changed), `sentenceAlternatives` (`sentenceId`, `sentence.pieces[0]`: takes, similar words and splices), `sentencePreview` (`sentenceId`; optional `sentence.pieces`, `sentence.alternative`, `sentence.version`, `sentence.timing`, `sentence.variant` `original`|`cleaned`; answers `{wav, revision}` as base64 WAV, 16 kHz for guests, one at a time and within the guest preview limit), `paletteSearch` (`query`, optional `sentence.voiceIds`, `sentence.altered`; answers `{items, activeSet}`), `paletteTap` with `action:"preview"` (`sentence.item`, 90 a minute for a guest), `performanceSets` without a write action (answers `{active, sets}`).
- **Build, host or `guestLibraryEdit`:** `sentenceCreate` (`sentence.text`, `sentence.origin` `typed`|`template`, optional `title`), `sentenceText` (`sentenceId`, `sentence.text`: rematches only the changed words), `sentenceEdit` (`sentenceId`, `sentence.do` = `move` | `edges` | `fade` | `gain` | `delete` | `pause` | `insertPause` | `missing` | `effects` | `settings` | `swap` | `resolve` | `shuffle` | `contrast` | `rematch` | `restore` | `pin` | `insert` | `title`, with the fields that action uses), `sentenceDiscard` (an unkept sentence by its maker; a kept one by the host only, leaving its audio files), `paletteMark` (`recordingId`, `name`, `sentence.startMs`/`endMs` up to 30 s; or `action:"remove"` with `sentence.item.namedId`, by who named it or the host), `performance` (`action` `start` | `stop` | `cancel` | `status`; `stop` answers `{sentenceId, taps}`). Unkept sentences are their maker's alone; a kept one changes only by its maker or the host. To anyone else, a kept sentence shows its latest kept version's text, pieces and settings (list, get, alternatives and preview), never edits not kept yet.
- **Keep, host or `guestKeep` with `guestLibraryEdit`:** `sentenceKeep` (`sentenceId`) renders the current revision and answers `{version, durationMs, revision}`. A guest's Keep is held against their permanent Keep budget when checked (over budget it is refused with a budget request), one at a time per guest, and the audio file it wrote is removed again if the change cannot be saved. At most 50 versions.
- **Playback intents:** `sentencePlay` (`sentenceId`, optional `sentence.version`) and `paletteTap` with `action:"game"` (`sentence.item`) are playback intents (2.35 rules) and control ops in the loopback server and the host page. The audio is rendered on the AudioWorker, written into an exact-playback slot and played; the playback record's id is `sentence:<id>` or `palette:<recordingId>`. Without `sentence.version`, `sentencePlay` renders the current revision; with it, it plays that kept file (SHA-256 checked). Guests need `remotePlayback`; a guest's `paletteTap` into the game and a `sentencePlay` without `version` also need `guestSeeking`, and ReserveIntent reserves nothing for them while it is off. Before playing, the companion checks again that the session is accepting, the guest is still allowed, playback is not suspended and (for rendered words) seeking is on; otherwise the answer is the quiet `superseded` / `suspended`. A newer intent cancels a render waiting for its turn or in progress (`superseded` / `newer`). A sentence longer than 120 s as laid out is refused before rendering. The slots are registered for sentences even when exact starts are off, at a quiet moment (waiting up to 2 s, otherwise "getting ready"); after a failed registration Play is refused at once for 30 s (60 s while the managed-audio journal is blocked).
- **Performance sets:** `performanceSets` with `action` `create` | `update` | `delete` | `activate` and `set` (`id` `default` or 32 hex, `name`, `voiceIds`, `favorites` as palette refs, `templates` `{id, name, text}`). Per person (host, or the guest's verified participant id): a `default` set and up to 31 more, references only, never audio.
- **Command fields:** `sentenceId` (32 hex); `sentence`, the strict `SentenceInput` object: `do`, `text` (≤ 4000), `pieces` (12-hex piece ids, ≤ 400), `offsetMs`, `startMs`, `endMs`, `fadeInMs`, `fadeOutMs`, `gain` (0–8), `balanced`, `durationMs`, `mode` `gap`|`bleep`, `effect` `{reverse, speed, keepPitch, echo}`, `chaos` (0–100), `timing` `fluent`|`original`, `balance`, `cleanup`, `altered`, `voiceIds`, `alternative`, `splice`, `word`, `version`, `pinned`, `variant`, `item` (a palette ref `{recordingId?, startMs, endMs, text, namedId?}`), `origin`; `set` (`PerformanceSetInput`). New `action` values: `game`, `preview`, `start`, `stop`, `cancel`, `activate`.
- **Threads:** every sentence and palette op runs off the receive loop after its intent is reserved, so arrival order is kept. Renders, encodes, previews and kept-audio reads run on the AudioWorker; game renders one at a time. `sentencePreview` and `sentenceKeep` use the slow-work slots, and the host page treats `sentencePreview`, `sentenceKeep` and `sentencePlay` as slow ops.
- **Guest limits:** 240 writes a minute per guest (create, text, edit, discard, keep, `paletteMark`, performance stop and set writes). Guests leave 400 of the 2000 sentences and 1000 of the 5000 named pieces to the host, and a guest's change may grow the sentences file only to 75% of its 64 MiB limit (shrinking is always allowed). Guests' unkept sentences untouched for 14 days are removed at the next create or performance stop. A performance holds at most 10 minutes and 400 taps of the recorder's own taps; labels past 4000 characters or 400 words stay in the take as pieces with no words of their own.
- **Snapshot:** `sentences`, a counter that rises when sentences, named pieces or performance sets change, so pages fetch `sentenceList`.
- **Files** (under the data folder's `library\`): `sentences.v1.json` (+ `sentences.v1.bak.json`; strict validation on load and before every save; a save over 64 MiB is refused; both damaged blocks writes and leaves the files untouched) and `sentences\<id>\v<N>-<hash8>.wav`, written once per kept version. `state.json` and the managed-audio journal are unchanged.

## Studio layout (2.43)

Three companion features, each behind a website gate in `FEATURES` (`web/src/version.ts`), all `[2, 43]`. Hosts on an older companion see the rest of 2.43 without them. `state.json` and the managed-audio journal are unchanged.

- **`kickSession`: snapshot `counterSession`.** Kick presses since this companion started, moving with the lifetime `counter` (never below 0); `reset` clears both. In memory only: a restart begins a new session at 0, and it is never written to `state.json`.
- **`soundEdit`: `TrimSource`.** `trimAudio` and `trimPreview` take exactly one source: `assetId` (a Temp asset, as before) or `soundId` (any sound in the Soundpad library, for Speed on a tile and the sound's editor). Both or neither is refused ("Choose one source to copy."), and so are `sentence:` and `palette:` ids. A `soundId` the companion manages is copied from its asset; any other from the file the companion's own library index names, never a path from the command. A file that cannot be decoded is refused with "That sound file could not be read." Permissions are unchanged: the host, or guests allowed to add audio; `trimPreview` is host only.
- **`uiSync`: `uiPrefsGet` and `uiPrefsSet`, snapshot `uiRevision`.** Host only (a guest gets "Host permission required."). `uiPrefsSet` carries `uiPrefs`, any subset of `navStyle` (`sidebar`|`tabs`), `theme` (`red-blue`|`purple`|`ocean`), `motion` (`system`|`reduce`), `contrast` (`standard`|`high`), `headerAnimation` (`on`|`still`|`off`) and `activeDraft` (`{sessionId, draftId}` or `null`), strictly typed, with any other key refused. Both answer `{ prefs, saved }`: every field filled in (defaults for what was never set) and whether `ui.json` exists. Each set raises `uiRevision` (in memory) and publishes, so the host's other pages fetch `uiPrefsGet`. Guests' pages never send these, and the example answers them as unavailable.
- **File:** `<data>\ui.json`, `{"version":1, …}`, written through a temporary file and a move. Unknown keys in the file are kept and written back, so a newer website's settings survive an older one's write. A known field with a value this version cannot read falls back to its default; a file over 4 KiB, one that is not JSON, or one with a key written twice reads as the defaults with `saved:false` and is left on disk until the next set replaces it. Older companions ignore the file.
